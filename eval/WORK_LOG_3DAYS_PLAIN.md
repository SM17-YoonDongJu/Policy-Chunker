## 1. 배경 — 보험약관 PDF는 어떤 물건인가

일반 문서가 아니다. 실제로 우리가 다루는 파일들의 규모다.

| 약관 | 특약 개수(목차 기준) | 잘라낸 조각 수 |
|---|---|---|
| 메리츠 단체안심생활보험 | 161개 | 1,878개 |
| DB 프로미라이프 참좋은더보장간병 | 132개 | 3,212개 |
| 삼성 건강보험천만안심 | 521개 | 10,030개 |
| KB 금쪽같은 자녀보험Plus | 904개 | 7,452개 |
| 현대 굿앤굿2040 종합보험 | 898개 | 13,107개 |

**한 파일 안에 계약서가 수백 개 들어 있다**고 보면 된다. 구조는 이렇다.

```
[ 보통약관 ]  ← 모든 가입자에게 공통 적용되는 본문
  제1조 … 제30조

[ 특별약관 1 ] 상해사망 특별약관        ← 여기서 조 번호가 제1조로 되돌아간다
  제1조 … 제5조
[ 특별약관 2 ] 골절진단비 특별약관       ← 또 제1조로 되돌아간다
  제1조 … 제4조
   …  (이런 게 수백 개)

[ 별표 ]  장해분류표, 수술분류표, 질병분류표 …  ← 수백 행짜리 표
```

### 여기서 나오는 유일한 진짜 난제

**"특약이 바뀌는 지점"을 못 알아채면 그 뒤가 전부 어긋난다.**

새 특약의 제1조를 앞 특약의 조항으로 착각한다. 그러면 앞 특약은 제1조가 두 개인 이상한
문서가 되고, 새 특약은 이름을 잃는다. 목차 페이지 번호가 한 번 밀리면 뒤가 다 틀리는 것과
같은 종류의 사고다. 3일간의 작업 절반이 이 한 문제였다.

## 2. 전체 흐름 — 무엇이 어떤 순서로 일어나는가

```
 ①  PDF 읽기        글자 + 글자 크기/굵기 + 표의 위치를 뽑는다
        ↓
 ②  특약 경계 찾기   "○○ 특별약관" 제목 줄을 찾아 문서를 구획으로 나눈다   ← 문제 1
        ↓
 ③  조 단위로 자르기  "제3조(보험금의 지급사유)"를 기준으로 나눈다          ← 문제 2
        ↓
 ④  긴 조항 더 쪼개기 400단어 넘는 나열형 조항만 1호·2호 단위로              ← 문제 3
        ↓
 ⑤  조각 저장        조각마다 [보험사 / 상품 / 특약 이름 / 조 번호]를 머리에 붙인다
        ↓
 ⑥  두 방식으로 색인  ㉠ 단어 그대로 찾기   ㉡ 의미가 비슷한 걸 찾기
        ↓
 ⑦  검색            두 결과를 합친 뒤, 다시 한 번 정밀 채점해 순서를 정한다   ← 문제 4
```

⑤에서 머리에 붙이는 정보가 왜 중요한가 — 조각 하나만 떼어 놓고 보면
"1. 전문등반, 글라이더 조종, 스카이다이빙…"이 **어느 상품 어느 특약의 면책 사유인지**
알 수 없다. 그래서 조각마다 출처를 새겨 넣는다.

```
메리츠화재 | 단체안심생활보험 | 직무상 선원 상해사망후유장해 특별약관 | 제3조(보험금을 지급하지 않는 사유)
```

②가 틀리면 이 머리표가 틀린다. 즉 ②의 실패는 **틀린 답을 자신 있게 내놓는** 실패다.

## 4. 고친 문제 ① — 특약 제목을 못 읽던 문제

### 증상

한 문서는 특약이 144개인데 **92개만** 찾았다. 52개는 이름 없이 앞 특약에 흡수됐다.

### 왜 어려운가 — 제목이 온갖 방식으로 망가져 있다

| 상황 | 실제 모습 |
|---|---|
| 두세 줄로 접힘 | `갱신형 중증화상 및 부식` ⏎ `진단비 특별약관` |
| 앞 문장 꼬리가 붙음 | `…지급합니다. 상해사망 특별약관` |
| 목차 점선과 헷갈림 | `1. 상해사망보험금 ………… 15` |
| 하이픈 번호 | `2-1. 갱신형 중증화상환자 진단비 특별약관` |
| 장 구분이 끼어듦 | `제2절 보장조항` 이 진짜 제목 앞에 먼저 나옴 |

### 어떻게 고쳤나

제목 후보를 보자마자 확정하지 않는다. **일단 모아뒀다가, `특별약관`·`보통약관` 같은
꼬리말이 나타나는 순간 하나로 합친다.** 제목은 반드시 그 꼬리말로 끝나기 때문이다.
줄이 세 줄로 접혀 있어도 꼬리말은 마지막 줄에 있으니 합쳐서 복원된다.

## 5. 고친 문제 ② — 다른 법을 인용한 문장이 조 번호를 덮어쓰던 문제

이게 3일 중 가장 지독했다. 원인이 **두 가지**였고, 두 번째는 오류 메시지조차 없었다.

### 사례 A — 조항이 산산조각 났다 (성폭력범죄상해 특별약관)

약관 원문이 이렇게 생겼다.

```
제1조(보험금의 지급사유)
 ① 회사는 보험기간 중에 피보험자가 다음 각호에서 정하는 성폭력범죄로 …
   1. 형법 제32장 강간과 추행의 죄 중
      제297조(강간)
      제298조(강제추행)
      제299조(준강간, 준강제추행)
      제300조(미수범)
      제301조(강간 등 상해·치상)
      제302조(미성년자등에 대한 간음)
        …
```

프로그램에게 `제297조(강간)` 은 **`제3조(보험금의 지급사유)` 와 똑같은 모양**이다.
"제N조(제목)". 그래서 인용 목록 한 줄 한 줄을 새 조항의 시작으로 보고, 하나의 조항을
아홉 조각으로 찢어놨다. 이 특약 하나에서 조번호 갭이 **9군데** 생겼다.

### 사례 B — 오류 없이 조용히 조 번호가 갈아치워졌다 (간편31·통합간편)

```
… 「국민건강보험법」에서 정한 요양급여 또는
「의료급여법」에서 정한 의료급여(이하 「의료급여」라 합니다)의 절차를 …
   제10조(급여비용의 부담)  동법 시행령
   제13조(…)
```

우리에겐 이미 안전장치가 있었다 — **"조 번호는 커지기만 한다"**. 그런데 정상적인
조 건너뛰기(제3조 → 제7조)도 있으니 너무 엄격하면 안 돼서, **현재 번호 +10 이내면
받아주는** 여유를 뒀다.

문제는 인용된 법의 조 번호가 하필 그 범위 안에 들어올 때다. 줄바꿈 때문에 `제10조(` 가
줄 맨 앞에 오고, 조항 제목 모양과 정확히 일치하고, 앞 번호와 10 이내라 안전장치도 통과한다.
**아무 경고 없이** 국민건강보험법 조 번호로 갱신되면서, 실제 제4~9조가 밀려나 사라졌다.

### 구별 기준 두 개

**㉠ 진짜 조항은 제목 뒤에 본문이 따라온다. 인용 목록은 제목만 줄줄이 이어진다.**

```
진짜:  제3조(정의)          ← 제목
       이 약관에서 …          ← 본문이 따라온다  ✅

인용:  제297조(강간)         ← 제목만
       제298조(강제추행)      ← 또 제목만
       제299조(준강간…)       ← 또 제목만        ❌ 3줄 이상 연속 → 인용
```

**㉡ 바로 윗줄이 "법 / 법률 / 시행령 / 시행규칙 / 규정 / 고시"로 끝나면 그 뒤 번호는 인용이다.**
"동법", "및" 같은 접속어는 잡을 수 없었지만, **한 줄 위에 법 이름은 그대로 남아 있었다.**

## 6. 고친 문제 ③ — "보험금 안 주는 경우" 질문에 유독 약했던 이유

### 증상

면책 질문 7개 중 5개의 정답이 **같은 조항 하나**에 몰려 있었다. 그 조항이 이렇게 길다.

```
제5조(보험금을 지급하지 않는 사유)                       ← 약 700단어, 통짜 한 덩이
 ① 회사는 다음 중 어느 한가지로 …
   1. 피보험자가 고의로 자신을 해친 경우 …
   2. 보험수익자가 고의로 피보험자를 해친 경우 …
   3. 계약자가 고의로 피보험자를 해친 경우
   4. 피보험자의 임신, 출산(제왕절개를 포함합니다), 산후기 …
   5. 전쟁, 외국의 무력행사, 혁명, 내란, 사변, 폭동
 ② … 아래에 열거된 행위로 인하여 …
   1. 전문등반, 글라이더 조종, 스카이다이빙, 스쿠버다이빙, 행글라이딩, 수상보트, 패러글라이딩
   2. 모터보트, 자동차 또는 오토바이에 의한 경기, 시범, 흥행 …
```

**"스카이다이빙 하다 다치면 보험금 나와?"** 라고 물으면, 정답이 이 안에 분명히 있는데
검색이 못 찾았다. 이유는 단순하다 — 700단어 덩어리에서 "스카이다이빙"은 전체의 0.5%다.
**단어 밀도가 희석돼 후보 목록에조차 오르지 못한다.**

### 원인을 어떻게 확정했나

비교군이 있었다. 같은 문서를 다른 방식으로 자른 참조본이 **이 유형만** 강했다(0.86).
차이는 단 하나, **조항을 1호·2호 단위로 쪼개 뒀다는 점**이었다.

결정적 증거는 검색 방식별 격차였다.

| 검색 방식 | 우리 | 참조본 | 해석 |
|---|---|---|---|
| 단어 그대로 찾기 | 0.29 | **0.71** | 여기만 2배 이상 벌어짐 |
| 의미로 찾기 | 0.43 | 0.43 | **완전히 동일** |
| 정밀 재순위 | 0.57 | **0.86** | 후보에 들어오니 이김 |

의미 이해가 좋아서가 아니다. **잘게 나눠 단어 밀도가 올라간 것**이 유일한 원인이었다.

### 조치 — 다 쪼개면 안 된다

전부 쪼개면 문맥이 깨진다. 그래서 **길고(400단어↑) 항목이 많은(4개↑) 나열형 조항만**
1호·2호 단위로 나누고, 도입 문장은 각 조각에 복사해 붙였다.

실제로 어떻게 바뀌었나 — 같은 내용, 같은 문서:

```
[ 이전 ]  682단어 한 덩이
메리츠화재 | 단체안심생활보험 | 제5조(보험금을 지급하지 않는 사유)
  ① 회사는 … 1. 고의로 자신을 해친 경우 … 2. 보험수익자가 … 3. 계약자가 …
  4. 임신, 출산 … 5. 전쟁, 혁명, 내란 … ② … 1. 전문등반 … 스카이다이빙 … 2. 오토바이 …

[ 이후 ]  142단어 조각으로 분리
```

## 7. 고친 문제 ④ — 측정용 코드는 맞는데 실제 서비스 코드만 틀렸던 버그 2개

성능 측정 코드와 실제 돌아가는 코드를 나란히 놓고 읽다가 나왔다. **둘 다 성능이 아니라
"틀린 설정"이었고, 아무 오류도 내지 않고 있었다.**

**버그 1 — 질문에 붙이는 안내문이 빠져 있었다.**
우리가 쓰는 검색 모델은 질문 앞에 정해진 문구를 붙여야 제 성능이 난다(문서에는 안 붙인다 —
질문과 문서를 다르게 다루도록 만들어진 모델이다). 측정 코드는 붙이는데 서비스 코드는
안 붙였다. 즉 **실제 서비스가 우리가 발표한 수치보다 낮게 동작하고 있었다.** 질문 쪽만
바뀌므로 저장된 데이터는 다시 만들 필요가 없었다.

**버그 2 — 존재하지 않는 모델 이름을 기본값으로 갖고 있었다.**
설정을 따로 지정하지 않으면 없는 모델을 부르며 실패했다. 실제 이름을 목록에서 확인해 맞췄다.

둘 다 원인이 같다 — **같은 값을 두 곳에 따로 적어뒀다.** 그래서 값을 맞추는 데서 끝내지
않고, 한 곳에서만 정의하고 나머지가 가져다 쓰도록 바꿨다.

## 8. 정답지가 없는데 어떻게 채점했나 (이번 작업에서 가장 쓸 만한 부분)

경계를 잘 잡았는지 채점하려면 정답이 필요하다. 그런데 없었다.

- 사람이 손으로 표시하기엔 **문서당 특약이 132~904개**다.
- 비교용으로 쓰려던 AI 참조본은 **그 자체가 쪼개져 있어** 정답이 못 됐다.

### 해결 — 약관의 목차를 정답으로 썼다

목차는 **문서가 스스로 적어둔 특약 제목 목록**이다. 공짜 정답표다.
번호와 공백만 맞춰 비교하면 정확도와 재현율이 바로 나온다.

실제 채점 결과는 이렇다. 여기서 우리 실력이 정직하게 드러난다.

| 보험사 / 약관 | 목차 제목 수 | 우리가 만든 구획 | 점수 | 못 살린 제목 |
|---|---|---|---|---|
| DB 빅히트 (동부) | 300 | 355 | **0.987** | 4 |
| 현대 굿앤굿2040 | 898 | 482 | 0.866 | 120 |
| 메리츠 단체안심생활보험 | 161 | 154 | 0.851 | 24 |
| 삼성 건강보험천만안심 | 521 | 299 | 0.484 | 269 |
| KB 금쪽같은 자녀보험 | 904 | 301 | **0.44** | 506 |
| DB 프로미라이프 간병 | 132 | 48 | **0.28** | 95 |

**보험사별로 실력이 완전히 다르다.** 잘 되는 문서(0.987)만 보고 있으면 다 된 것처럼 보이고,
KB·삼성·DB프로미라이프는 아직 절반도 못 잡는다. 이 표가 다음에 할 일을 정해준다.

### 실제로 뭘 놓쳤는지도 보인다

```
놓친 제목:  '유상운송관련담보'
            '상해위험담보'
            '진단비및위로금담보등기타비용담보'
```
→ `특별약관` 꼬리말이 없고 `담보`로 끝나는 제목들이다. 우리 규칙이 꼬리말을 요구하니 못 잡는다.

```
잘못 잡은 제목:  '제2호에서정한조건을만족하지않아이특별약관'
```
→ 본문 문장 중간에 `특별약관`이라는 말이 나와서 제목으로 착각했다. 지금은 이런
**문장 조각 제목을 차단하는 규칙**이 들어가 있다.

### 곁들여 만든 두 장치

**㉠ 상시 채점 — 세 문서로 시작해 20개 약관 전체로 넓혔다.**
왜 넓혔나: 세 문서만 보면 "이 문서에서 고친 규칙이 **다른 문서를 깨뜨렸는지**"를 알 수 없다.
실제로 두 번 깨뜨렸다(다음 장).

**㉡ "나쁜 숫자"와 "원래 그런 숫자"를 분리했다.**
조 번호가 비어 있는 조각을 그냥 세면 지표가 나빠 보인다. 그런데 **별표나 특약 도입 문장은
원래 조 번호가 없다.** 이걸 걸러내자 한 문서의 복원율이 **98%**로 잡혔다.
나빠 보였던 것 상당수가 실은 정상이었다는 뜻이다. 지표를 고치는 것도 일이다.

## 9. 고치려다 오히려 망가뜨린 두 번 — 이게 교훈이다

두 번 모두 **원인을 확인하기 전에 방어 코드를 넣어서** 생겼다.

### 첫 번째 — 정상 조항까지 걸러버렸다

인용 목록을 막으려고 "**제목만 있는 줄은 무조건 건너뛴다**"고 정했다. 그런데 이런 정상
조항이 있었다.

```
제3조(정의)
제4조(청구서류)        ← 본문이 옆의 표 안으로 들어가서 제목만 남았다. 정상 조항이다!
```

다른 문서(출산비용 특별약관)가 갭 0 → **4로 새로 깨졌다.**
→ 진짜 인용은 5줄 이상 연속, 정상 조항은 1~2줄뿐이라는 차이로 **"3줄 이상 연속일 때만"**
으로 완화했다. 그 문서는 정상 복귀, 나머지 19문서 변화 없음.

### 두 번째 — 있지도 않은 위험을 막다가 정상 한국어를 걸렀다

"혹시 `의료법`의 `의`가 조사로 오인될 수도 있으니" 하고 조건을 하나 더 걸었다.
그 위험은 **한 번도 실제로 관측된 적이 없었다.** 대신 이런 정상 표현을 걸렀다.

```
"제3항에서 정한 …"    ← 조사가 붙는 지극히 정상적인 한국어
```

문서 3개가 새로 깨졌다. → 확인 없이 넣은 조건을 **제거**했다. 목표였던 문서는 갭 6 → 0,
나머지 19문서 변화 없음.

### 여기서 남는 원칙

> **가상의 위험을 막는 코드가, 실재하는 정상 케이스를 깨뜨린다.**
> 두 번 다 "그럴 것 같아서"가 아니라 **측정으로** 되돌렸다.

## 10. 해봤는데 버린 것 두 개 (실패도 기록한다)

### ㉠ 표 깨짐을 AI 이미지 인식으로 고치려던 시도 — 무개선

표 깨짐이 가장 심한 문서(**21.4%**)에 AI 이미지 인식을 적용했다. 결과 **20.8%**.
35분 들여 사실상 그대로였다.

원인이 인식 품질이 아니었기 때문이다. **여러 줄이 합쳐진 칸을 한 줄로 펴는 단계에서
값이 뭉친다.** 실제 모습을 보면 바로 이해된다 — 장해분류표에서 뽑아낸 표다.

```
| 장해의 분류                                   | 지급률                  |
| 1) 두 눈이 멀었을 때  2) 한 눈이 멀었을 때
  3) 한 눈의 교정시력이 0.02 이하로 된 때
  4) 한 눈의 교정시력이 0.06 이하로 된 때 …      | 100 50 35 25 15 5 10 5 10 5 |
```

항목 10개가 한 칸에, 지급률 10개가 다른 한 칸에 들어갔다. **사람은 짝을 맞춰 읽지만,
"한 눈의 교정시력 0.06 이하면 몇 %?"라는 질문에 프로그램이 짝을 틀릴 수 있는 형태다.**
인식기를 바꿔선 안 풀리고, 합쳐진 칸을 가진 표만 원래 구조로 보존해야 한다.

### ㉡ 해외 사례가 지목한 원인 — 우리 데이터에는 해당 0건

해외 자료가 "면책 조항이 보장 조항과 떨어져 있어 문맥이 부족한 것"을 원인으로 지목했다.
우리 실패 사례 7건을 전수 확인한 결과 **해당 0건**이었다.
한국 약관 면책 조항은 **그 자체로 완결된 목록**이어서 이 틀이 맞지 않았다.
실제 원인은 6장(조각 크기)이었다.

> 외부 프레임을 우리 데이터로 검증한 뒤 폐기한 사례다. 읽고 그대로 따라 했으면
> 엉뚱한 걸 3일 더 고쳤을 것이다.
